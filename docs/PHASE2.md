# 2단계 작업 지시서 — 내 목록 기반 팀 추천 (웹)

작업 전 `docs/ROADMAP.md` 를 먼저 읽는다. 오버레이·녹화 판독·이메일 로그인은 범위 밖.

## 작업 규칙
- `main` 기준 새 브랜치 + 새 PR. 병합하지 않는다.
- 커밋마다 `npm run build` 통과.
- "없다/불가능하다" 판단 시 확인한 경로·명령·응답을 근거로 첨부.
- **팀 선정은 서버 계산(결정적)으로 한다. AI(Gemini)는 선정하지 않는다.** AI 호출은 사용자가 "박사 코멘트" 버튼을 누를 때만 1회. (고급 모델 무료 한도가 약 20회로 확인됨)

## 0. 선행: 목록에서 기술 편집
- 내 목록 ✏️ 편집에 빠른 기술·차징 기술(최대 2개) 선택 추가. 선택지는 해당 종·폼의 기술 목록(일반/레거시/전용기/한정기 구분 표시)만.
- 기술이 비어 있는 항목은 "기술 미입력" 표시.

## 1. 공통 계산 모듈 (`app/lib/teamScore.js`)
기존 천적 후보 점수(0-후속) 로직을 재사용·확장한다.

- **레벨 추정**: CP·개체값·종족값·CP 배율표로 레벨 계산(0.5 단위). 개체값 미입력이면 10/10/10 가정 + "추정" 표시. CP 없으면 레벨 40 가정.
- **실제 능력치**: (종족값 + 개체값) × CP 배율. 그림자는 공격 ×1.2, 방어 ×0.833.
- **기술**: 저장된 기술 사용. 미입력이면 그 종의 최고 조합으로 계산하고 "기술 미입력 — 최적 기술 가정" 표시.
- **레이드 점수**: 보스 대상 간이 DPS(빠른 n회 + 차징 1회 사이클, 자속 1.2, 타입 배율, 보스 방어력 반영) × 생존력 보정(보스 타입 자속 공격에 대한 받는 배율과 내 방어·체력으로 계산한 간이 버티기 시간). 수식과 가정을 코드 주석과 README 에 명시.
- 제외: `status = 'transfer'`(박사행) 항목.

## 2. 레이드 팀 추천
- 진입: 레이드 탭의 현재 레이드 목록에서 보스 선택, 또는 검색.
- 결과: 내 목록 상위 6마리 (종·CP·기술·점수·보스 대비 배율·추정 여부 표시).
- 같은 종이 여러 마리면 중복 허용(실제 레이드처럼).
- 내 목록에 쓸 만한 포켓몬이 6마리 미만이면 부족분을 "구하면 좋은 포켓몬"(기존 천적 후보)으로 채워 구분 표시.
- 보스 타입의 기술로 내 팀이 약점을 찔리는 경우 경고 표시(예: 팀 6마리 중 4마리가 보스 자속 기술에 약점).

## 3. 로켓단 팀 추천
- 데이터: ScrapedDuck `https://raw.githubusercontent.com/bigfoott/ScrapedDuck/data/rocketLineups.min.json`
  (26개 라인업, 항목: `name`, `title`, `type`, `firstPokemon[]`, `secondPokemon[]`, `thirdPokemon[]` — 각 포켓몬은 `name`, `types[]`). 서버 캐시 6~12시간, 장애 시 해당 기능만 비활성화 + 안내.
- 진입: 로켓단 탭 신설 → 조무래기(타입별)·간부·보스 선택.
- 결과: 슬롯별(1·2·3번째) 가능한 포켓몬 전체를 고려해 내 목록에서 3마리 추천. 슬롯마다 가장 유리한 1마리를 우선하되, 한 마리가 여러 슬롯을 커버하면 표시.
- 점수: 로켓단 전투는 실드·에너지가 있는 1:1 전투이므로 레이드 DPS 대신 "빠른 기술 에너지 효율 + 차징 기술 위력 + 타입 배율 + 내구" 간이 점수. 가정을 명시하고 "간이 추천" 표기.

## 4. 맥스배틀 (조건부)
- 다이맥스·거다이맥스 가능 여부 데이터를 교차검증 소스에서 확인. 확인되면 맥스배틀 보스 대상 3마리 추천(레이드 점수 재사용, 다이맥스 가능 포켓몬만).
- 데이터가 없으면 구현하지 말고 근거와 함께 보고.

## 5. 박사 코멘트 (선택)
- 팀 결과 아래 "🧠 박사 코멘트" 버튼 → 서버가 계산한 팀·점수·가정을 Gemini 에 넘겨 3~5줄 해설. AI 는 팀을 바꾸지 않는다(프롬프트에 명시). 사용 횟수에 포함.
