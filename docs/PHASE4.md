# 4단계 작업 지시서 — 용도별 보관 판정 · 목록 관리 · 이벤트 연동

작업 전 `docs/ROADMAP.md` 를 먼저 읽는다. **4-0 → 4-A → 4-B(연속 스캔 포함) → 4-C(기술 스캔)** 순서로 각각 별도 PR.

## 4-0. 웹 화면을 수집기 앱에 통합 (먼저, 작은 PR)
- 문제: 웹앱은 익명 세션이 브라우저에 있어 창을 닫거나 인앱 브라우저·시크릿이면 계정을 잃는다. 사용자는 앱 1개로 쓰길 원함.
- 수집기 앱에 "포고박사" 탭(또는 첫 화면 버튼) 추가: WebView 로 `serverUrl` 웹앱을 연다.
- **자동 로그인**: 앱이 기기 토큰으로 `/api/device/web-code` 발급 → WebView 안에서 `/api/auth/web-login` 교환(3-1c 흐름 재사용)해 앱 계정 세션으로 진입. 코드는 화면에 표시하지 않음. 세션이 이미 같은 user_id 면 생략.
- WebView 보안: 우리 도메인만 로드(그 외 링크는 외부 브라우저), JavaScript 브리지 노출 최소화(필요 시 토큰 원문은 넘기지 말고 1회용 코드만), 파일 접근 비활성, 뒤로가기 처리.
- 웹은 PC 등에서 계속 쓸 수 있음(앱 → 웹 로그인 코드). 웹의 "홈 화면에 추가"(PWA manifest 기존재)는 안내만.
- 완료 기준: 앱에서 웹 화면 열기 → 자동으로 앱 계정 목록 표시, 앱 재시작 후에도 유지, 외부 링크는 브라우저로.

## 배경
- 현재 판정(앱 `android/core/.../Verdict.kt`, 웹 Gemini 판정)은 **개체값만** 보고 종족 가치를 보지 않는다. "보관"은 항상 `purposes = []` 로 저장된다.
- 사용자 목표: 캡처 1회로 "무슨 용도로 보관할지(추천 태그)" 또는 "박사행"을 판단받고, 박사행 후보 안에서도 **수집 가치**가 있는 개체는 건진다. 포켓몬GO 태그는 사용자가 게임에서 직접 단다(자동 조작 금지 규칙 유지).

## 원칙
1. **결정적 계산**. AI(Gemini)는 판정에 쓰지 않는다(무료 한도·비일관성). AI 는 기존 "박사 코멘트" 해설로만 유지.
2. 판정은 **저장하지 않고** 볼 때마다 계산(1단계 원칙 유지). 저장하는 것은 사용자가 확정한 `status`·태그뿐.
3. 앱·웹이 **같은 서버 계산**(`POST /api/verdict`)을 쓴다. 앱 오프라인 시에만 기기 내 간이 계산 + "간이 판정" 표시.
4. 기준값은 상수 파일 하나(`app/lib/verdictRules.js`)에 모으고 README 에 표로 기록 — 이후 조정 가능해야 한다.
5. 레이드 판단에서 **전체 %는 쓰지 않는다**. 레이드 대미지는 공격 스탯에 비례하며 영향 순서는 종족 > 섀도 > 강화 레벨 > 공격 개체값(에이스번 기준 공격 IV 15 vs 13 = +0.8%, L40→50 = +6.3%).

## 4-A. 용도별 보관 판정

### 1) 판정 단계
| 단계 | 의미 |
|---|---|
| ✅ 주력 | 해당 용도에서 내 보관함 최상위권. 강화 투자 추천 |
| 🟡 보류 | 쓸 수는 있으나 주력 아님. 보관함 여유 설정에 따라 보관/박사행 |
| ❌ 박사행 | 어느 용도에도 해당 없음 |
| 💎 수집 추천 | 위 판정과 별개로 붙는 표시 (박사행이어도 "단, 수집 추천" 가능) |

### 2) 추천 태그(용도 이름)와 기준 (초기값)
한 개체에 여러 태그 가능. 태그 문자열은 사용자가 게임에서 그대로 쓸 수 있는 한국어.

| 추천 태그 | 종족 조건 (자동 산출, 손목록 금지) | 개체 조건 → 주력 / 보류 |
|---|---|---|
| `{타입} 레이드` (예: 불꽃 레이드) | 18개 타입별로 출시 확인된 종의 레이드 점수(teamScore 의 DPS^0.775×TDO^0.225, 그 타입 기술 기준) 순위. **12위 이내** = 상위종, 13~30위 = 중위종. 섀도는 별도 순위, 메가는 제외(참고 표기만) | 내 목록 같은 종·같은 용도 안에서 공격 스탯(공격 IV 우선, 동률 시 레벨) 순위. 상위종 & 순위 ≤ 6 → 주력. 상위종 순위 7+ 또는 중위종 → 보류 |
| `체육관 방어` | 전설·환상 **제외**(체육관 배치 불가), 방어×HP 기반 내구 순위 상위 20종 | 같은 종 내 상위 2 → 주력, 그 외 보류 |
| `슈퍼리그` / `하이퍼리그` | PvPoke `rankings/all/overall/rankings-1500.json`·`-2500.json` (존재 확인됨) 상위 100위 = 상위종, 101~200 = 중위종 | 리그 스탯곱(공×방×HP, CP 상한 내 최고 레벨, 레벨 상한 50 기본·51 옵션) 순위(4096 중). 상위종 & ≤100 → 주력, 상위종 ≤500 또는 중위종 ≤100 → 보류. **현재 CP 가 상한 초과면 해당 리그 불가** |
| `마스터리그` | `rankings-10000.json` 상위 50위 | 전체 ≥96% → 주력, 91~95% → 보류 |
| `진화 대기(→최종형)` | 진화 계열 최종형(분기 진화는 각각) 기준으로 위 태그 평가 | 최종형 기준 주력/보류이면 부여. 사탕 수를 읽었으면 "진화 가능/사탕 x/y" 표기 |

- **기술 반영**: 캡처로 읽은 기술로 레이드 점수 계산. 핵심 기술(전용기·레거시기)이 없으면 "특수 기술머신 필요" 표기, 종 순위는 최적 기술 기준 유지.
- 개체값이 **후보 여러 개**면 모든 후보에서 같은 판정일 때만 확정. 아니면 `need_appraisal`("평가 화면 캡처 필요").

### 3) 보관함 여유 설정 (사용자 설정, 기본 "보통")
| 설정 | 보류 처리 |
|---|---|
| 여유 | 보류는 모두 보관 권장 |
| 보통 | 보류는 같은 종·같은 태그 **2마리까지** 보관, 초과분 박사행 권장 |
| 빠듯 | 주력만 보관, 보류는 박사행 권장 |

### 4) 수집 추천 (💎)
| 사유 | 조건 |
|---|---|
| 희귀 | 이로치, 반짝반짝(럭키), 개체값 100%, 0%(0/0/0) |
| 전설·환상 | 개체 무관 보관 권장. 낮은 개체면 "교환용"(교환 시 개체값 재설정) |
| 교환용(오래된 포획) | 상세 화면 포획 날짜를 **기기 내에서만** 읽어 판단(서버 전송 금지). 교환 시 반짝반짝 확률이 오르는 기준 연도는 공식 근거로 확인 후 상수화 — 확인 불가 시 기능 비활성 + 보고 |
| 섀도·정화 전설 | 보관 권장 |

### 5) 이벤트 연동 (4-A 에 포함)
- 기존 `/api/events`(ScrapedDuck) 에서 **30일 이내** 커뮤니티 데이·스포트라이트 등 대상 종을 추출.
- 스캔한 종(또는 진화 계열)이 대상이면 판정에 "📅 {날짜} {이벤트} 대상 — 박사행 보류(이벤트 때 진화하면 전용 기술)" 추가, 박사행 → 보류로 상향.
- 대상 종 매칭 근거(이벤트 원문 필드)를 테스트로 고정.

### 6) API
`POST /api/verdict` (인증 선택: 웹 세션 또는 기기 토큰. 인증되면 내 목록 비교 수행)
- 입력: `species_id, form, ivCandidates[] 또는 ivs, levelRange, cp, hp, fast_move, charged_moves[], is_shadow, is_purified, is_shiny, is_lucky, candy?, storageMode?`
- 출력: `{ tier: main|hold|transfer|need_appraisal, tags: [{name, tier, reason, metrics}], collect: [{reason}], event?: {...}, confident: bool, basis: "server" }`
- 목록 일괄 판정: `POST /api/verdict/batch` (웹 내 목록용, 최대 500건)
- 캐시: PvPoke rankings·이벤트 6~12시간. 장애 시 해당 태그만 "데이터 없음".

### 7) 화면
- **앱 결과 화면**: 기존 한줄평을 대체. 예) `✅ 주력: 불꽃 레이드 (불꽃 3위·공격 15, 내 에이스번 중 1위)` / `❌ 박사행 → 💎 수집 추천: 교환용(전설)`. 버튼: [보관(추천 태그로 저장)] [박사행] [닫기]. 저장 시 추천 태그를 목록에 기록.
- **웹 내 목록**: 각 항목에 판정·추천 태그 표시(볼 때마다 계산), 태그·단계 필터. 분석 화면 판정도 이 API 로 교체(Gemini 는 코멘트만).
- 설정: 보관함 여유(여유/보통/빠듯).

### 8) 데이터 구조 (마이그레이션 0004, 멱등, 사용자가 SQL Editor 에서 실행)
- `my_pokemon.tags text[] not null default '{}'` — 사용자가 확정한 추천 태그(자유 문자열, 개수·길이 제한 서버 검증). 기존 `purposes` 는 유지하되 태그에서 파생해 채움(raid/great/ultra/master).
- `my_pokemon.hp integer`, `my_pokemon.caught_on date`(목록 매칭용. **장소는 저장하지 않음**).
- RLS 는 기존 정책 그대로 적용되는지 확인.

## 4-B. 평가 화면 연속 스캔 + 목록 관리 (PHASE3 의 3-2 연속 모드를 대체)

### 연속 스캔
- 사용자 동작: 포켓몬GO **평가 화면(막대 3개)을 켜 둔 채 좌우로 넘기기만** 한다. 버튼 없이 자동 분석.
- 캡처 서비스가 초당 2~3프레임 샘플 → 이름·CP 영역 변화 감지 → **막대가 안정(연속 2프레임 동일, 채움 애니메이션 종료)** 되면 1회 분석. 같은 개체(종·CP·HP·막대 동일)는 재분석·재기록 안 함.
- 평가 화면 1장에서: 이름·CP·HP·막대 3개·별 → 개체값 확정 + CP/HP 로 레벨 교차 확인. 불일치 시 "재확인 필요". 상단 안내 배너가 CP 를 가리면 사라질 때까지 대기.
- **게임 조작 방해 금지**: 연속 모드에서는 결과 액티비티를 띄우지 않는다(포커스·터치를 가져감). 표시는 ① 포그라운드 알림 한 줄 갱신("스캔 12 · 방금 에이스번 96% 주력: 불꽃 레이드") ② 오버레이가 보이는 환경이면 FLAG_NOT_TOUCHABLE·불투명도 ≤0.8 의 작은 띠(터치 통과, Android 12 untrusted touch 규칙 준수), 가려지면 알림만.
- **스캔 기록**: 세션별 목록(앱 화면 + 웹). 항목마다 4-A 판정. [추천대로 보관 저장] 일괄 / 개별 보관·박사행. **자동 저장 금지** — 저장은 사용자가 검토 후 확정.
- 기술은 이 모드에서 읽지 않음 → 판정에 "기술 미확인(최적 기술 가정)" 표기.
- 배터리·발열·프레임 처리 시간(A90) 측정값 보고. 모드 켜기/끄기는 타일·알림 버튼.

### 목록 관리

| 문제 | 구현 |
|---|---|
| 중복 저장 | `/api/device/pokemon` 과 웹 저장에 매칭: ① 종·폼·개체값(확정)·포획일 → ② 종·폼·CP·HP. 일치하면 새 행 대신 **갱신**하고 응답에 `updated: true` |
| 강화·진화 후 불일치 | 재캡처 시 ①로 매칭되면 CP·HP·레벨·기술·종(진화 시 계열 내 변경 허용) 갱신. 결과 화면에 "기존 항목 갱신" 표시 |
| 박사행 후 정리 | 웹 내 목록 "박사행 예정" 필터 → [보냄 처리] 일괄 삭제(확인 대화상자) |
| 수동 편집 충돌 | 갱신은 사용자가 편집한 메모·태그를 덮어쓰지 않음 |

## 4-C (재정의). 추천 기술 표시 · 강화/진화 후 동일 개체 갱신 · 정리 도우미 보완
1. **추천 기술 표시**: 보관(주력/보류) 개체마다 용도 태그별 추천 기술(빠른/차지)을 웹 목록·스캔 기록·앱 결과에 표시. 특수 기술머신이 필요하면 "⚠ 특수 기술머신", 30일 내 이벤트 대상이면 "📅 이벤트 때 진화". "기술 확인 필요(최적 기술 가정)" 문구는 "추천 기술: …" 로 교체(경고 아님).
2. **강화·진화 후 동일 개체 갱신** (`pokemonMatch.js` 규칙 ③): 같은 진화 계열·폼·섀도, 개체값 3개 확정·동일, 새 레벨 ≥ 기존 레벨(레벨 없으면 CP) → 같은 개체로 갱신(CP·HP·레벨·종 갱신, tags/status/memo/game_tags 유지). 후보 2개 이상이면 병합하지 않고 재확인 표시. 스캔 기록은 새 기록 insert 시 같은 조건의 과거 기록(다른 세션 포함)을 `superseded` 로 표시(0008) → cleanup·목록·stats 제외.
3. **게임 태그 vs 판정 불일치**: 게임 태그 우선(박사행 제외 유지). 웹에 "판정: 박사행 / 게임 태그: …" 불일치 표시만, 자동 변경 없음.
4. **태그 칩 판독(OCR·픽셀) 중단**: 평가 화면(연속 스캔)에는 태그가 보이지 않음(사용자 확인). 대신 박사행 검색어에 게임 검색 `&!#`(태그 없는 개체만)을 붙이는 옵션(기본 끔, 한국어판 동작은 사용자 확인 후).

## 4-D. 함께 처리 (이전 요청, 4-A 에 포함)
