## 1단계 설계 원칙

- 판정 결과는 저장하지 않는다. 개체값 판정은 볼 때마다 계산한다.
  - 같은 포켓몬도 용도(레이드 / 슈퍼·하이퍼·마스터리그)에 따라 평가가 달라지기 때문.
- 저장의 중심은 "내 포켓몬 목록"이다.
  - 저장 항목: 종·폼, CP, 개체값, 기술, 섀도·이로치·럭키 여부, 상태, 용도 태그, 등록 경로
  - 상태: 보관 / 박사에게 보낼 예정
  - 용도 태그: 레이드, 슈퍼리그, 하이퍼리그, 마스터리그 (여러 개 가능)
- 사용자별 완전 분리 (익명 계정으로 시작, 이메일 연결은 나중에).

## 보류 아이디어 (구현 금지, 기록용)

### 오버레이 (3단계 → docs/PHASE3.md 로 확정)
- 개체값 확인 화면에서 "보관 / 버리기" 버튼
  - "보관"을 누르면 내 포켓몬 목록에 자동 등록
  - → 1단계 데이터 구조에 반영됨: 등록 경로 필드(`source`: web / overlay), 상태 필드
- 레이드 카운터 추천을 오버레이에 표시
  - 레이드 보스 선택 방법 후보: ① 현재 레이드 목록(ScrapedDuck)에서 선택 ② 레이드 대기 화면을 인식해 자동 판별
  - 내 포켓몬 목록 중 추천 우선 표시

### 내 포켓몬 기반 팀 추천 → 2단계로 확정 (docs/PHASE2.md)
- 내 포켓몬 목록 안에서 최적 팀 구성
  - 레이드: 보스별 6마리 팀
  - 로켓단 배틀: 조무래기·간부·보스 라인업별 3마리 팀 (라인업 데이터: ScrapedDuck `rocketLineups.min.json`, 응답 확인됨)
  - 맥스배틀: 다이맥스·거다이맥스 가능 포켓몬 3마리 팀
- 전제: 1단계의 내 포켓몬 목록, 0단계 후속의 천적 후보 화력 점수 로직을 재사용
- 오버레이와 연결: 레이드·로켓단 전투 직전 화면에서 추천 팀 표시

### 맥스배틀 팀 추천 (보류)
- 교차검증 소스 어디에도 다이맥스 가능 여부 데이터가 없음 (PR #15 보고 근거)
- 재개 조건: 내 목록에 "다이맥스 가능" 사용자 입력 항목(`is_max`) 추가 후, 그 항목만 대상으로 레이드 점수 재사용
